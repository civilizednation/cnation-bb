# cnation 붕어빵 타이쿤: 스토리 모드 기획안

> 상태: **초안 (사용자 검토 중)**. 수치는 모두 첫 플레이테스트 전 **초기값**이며, 만든 뒤 직접 플레이하면서 조정합니다.
> 이 문서는 사용자가 정리한 아이디어 12가지를 검토해 다듬은 것입니다. 원래 아이디어와 달라진 부분은 **[변경]**, 새로 더한 부분은 **[추가]**로 표시했습니다.

## 3. 상점과 업그레이드

장사가 끝나면 정산 다음에 상점이 열립니다. 업그레이드는 **영구**(그 스토리 플레이 끝까지 유지)이고, 단계마다 가격이 오릅니다.

| 업그레이드 | 단계별 효과 | 가격 (초기값) | 열리는 날 |
|---|---|---|---|
| 🍳 **틀 추가** | 4칸(2×2) → 6칸 → 9칸 | 12,000 / 30,000 | Day 1부터 |
| 🔥 **화력 강화** | 굽는 시간 −10% → −20% → −30% | 6,000 / 14,000 / 26,000 | Day 1부터 |
| 🧯 **두꺼운 철판** | 타기까지 시간 +20% → +40% | 5,000 / 12,000 | Day 2부터 |
| 🛍️ **큰 봉투** | 봉투당 담을 수 있는 개수 6 → 9 → 12 | 4,000 / 10,000 | Day 3부터 |
| 📯 **간판** | 손님이 오는 간격 −15% → −30% | 8,000 / 20,000 | Day 3부터 |
| 💰 **가격 인상** | 개당 1,000 → 1,200 → 1,400원, 대신 인내심 −10% → −20% | 10,000 / 24,000 | Day 5부터 |

- **[변경] 큰 봉투:** 슈크림이 생기면 봉투가 **팥·슈크림 두 개**가 됩니다(5장). 그래서 "9 → 12"를 **봉투 하나당 6 → 9 → 12**로 바꿨습니다.
- **[추가] 열리는 날:** 첫날부터 모든 업그레이드를 보여 주면 고르기 어렵습니다. 그래서 날짜에 따라 하나씩 열리게 했습니다.
- **간판 + 가격 인상의 함정:** 둘 다 사면 손님은 많이 오는데 덜 참습니다. 틀이 적으면 오히려 만족도가 떨어질 수 있습니다. 이 선택이 전략의 핵심이 되도록 만듭니다.
- 상점에서는 사기 전에 **효과를 숫자로** 보여 줍니다. 예: "굽는 시간 6.0초 → 5.4초".

### 돈 밸런스 (예상)
- 하루 수입(재료비 빼기) 예상: Day 1 약 6,000원, Day 8 약 25,000원, Day 15 약 50,000원
- 15일 총 수입 예상: 약 **35만~45만 원**
- 업그레이드를 전부 사면 약 **21만 원**입니다. 그래서 "다 사고 끝내기"는 불가능하지 않지만 점수가 크게 줄어듭니다. 무엇을 살지 고르는 게 중요해집니다.
- 이 숫자는 첫 버전을 만든 뒤 직접 플레이하면서 다시 맞춥니다.

## 4. 손님 만족도

화면 위쪽(지금 판매 수가 있는 자리)에 **만족도 게이지(0~100%)**를 표시합니다. 하트나 얼굴 아이콘과 함께 보여 주고, **80%에서 시작**합니다.

### 올라가는 경우
| 상황 | 변화 |
|---|---|
| 빠르게 건넴 (인내심이 70% 넘게 남았을 때) | +3 |
| 보통으로 건넴 | +1 |
| 연속 성공 콤보 (3명째부터 한 명마다) | 추가 +1, 화면에 "🔥 3콤보!" 표시 |
| 완벽하게 구운 붕어빵 ("다 익었어요!" 직후 1초 안에 꺼냄)만 건넴 | 추가 +1 |

### 내려가는 경우
| 상황 | 변화 |
|---|---|
| 다른 종류를 건넴 (팥을 시켰는데 슈크림) | −2 (그 붕어빵은 손님이 돌려줌) |
| 덜 익은 붕어빵을 건넴 | −5 |
| 손님이 기다리다 떠남 | −8 |
| 붕어빵을 태움 | −1 (가게에 탄내) |

- **[변경] "주문 후 1초 안에 제공":** 손님이 여러 명 오면 1초는 거의 불가능합니다. 그래서 **남은 인내심 비율**로 판단합니다.
- **[변경] 태운 붕어빵:** 탄 붕어빵은 지금처럼 **봉투에 담을 수 없고 버리기만** 합니다. 탄 것을 손님에게 줄 수 있으면 실수로 주게 되어 억울하기 때문입니다. 대신 태우는 것 자체에 작은 벌점(−1)을 줍니다.
- **[추가] 덜 익은 붕어빵:** 스토리 모드에서는 두 번째 면을 굽는 중(지금의 "굽는 중")에도 꼬챙이로 **급하게 꺼낼 수 있게** 합니다. 바쁠 때의 유혹입니다. 덜 익은 붕어빵은 연한 색으로 보이고, 건네면 −5입니다.
- **만족도 0%** → 바로 게임 오버 (6장)
- 하루가 끝나면 정산 화면에 만족도 변화를 보여 줍니다. 예: "오늘 만족도 80% → 86% (빠른 제공 12번, 떠난 손님 1명)".

## 5. 슈크림, 봉투 두 개, 섞은 주문

### 굽는 순서
1. 반죽을 붓습니다.
2. **팥** 또는 **슈크림**을 올립니다. 도구가 4개가 됩니다: 반죽 · 팥 · 슈크림 · 꼬챙이
3. 지금처럼 두 번 뒤집습니다.
4. 꼬챙이로 꺼내면 **종류별 봉투**(팥 봉투 / 슈크림 봉투)에 자동으로 들어갑니다.

- 뒤집으면 겉모습이 같아서 무엇이 든 붕어빵인지 모릅니다. 그래서 틀 위에 **작은 종류 표시(팥 / 슈크림 아이콘)**를 붙입니다.
- 슈크림 재료비는 팥보다 조금 비쌉니다(반죽 300원 + 슈크림 100원). 대신 가격도 개당 +200원입니다.

### 건네는 방법 [변경 내용 그대로 반영]
- 손님이 "팥 2개, 슈크림 1개"를 시키면 **팥 봉투 2번, 슈크림 봉투 1번** 터치합니다.
- 터치할 때마다 한 개씩 건네지고, 주문표의 해당 칸이 하나씩 채워집니다. 다 채우면 손님이 만족하고 떠납니다.
- 주문에 없는 종류를 건네면 "그거 말고요!" (−2), 그 붕어빵은 봉투로 돌아옵니다.
- 봉투에는 넣은 순서대로 쌓이고, 먼저 넣은 것부터 나갑니다. 덜 익은 붕어빵을 넣었다면 먼저 나갈 수 있습니다.

### 섞은 주문
- Day 8부터 한 손님이 두 종류를 함께 시킵니다. 예: "팥 2개랑 슈크림 1개요!"
- 말풍선 글자만으로는 읽기 어려우니, 주문표에 **아이콘 + 숫자**로 보여 줍니다. 예: 팥 아이콘 ×2 · 슈크림 아이콘 ×1

## 6. 손님 여러 명: 화면 구성

지금은 손님 1명과 큰 말풍선이 위쪽을 다 차지하고 있어서, 손님이 여러 명 오려면 화면을 다시 짜야 합니다.

### 제안하는 배치 (360×640 기준)
```
┌──────────────────────────────────────┐
│ 차양                                   │
│ ⏱ 0:42   💰 12,400   😊 ████░ 84%  ⏸ 🔊 │  ← 판매 수 자리에 만족도
│                                        │
│   [손님 1]     [손님 2]     [손님 3]    │  ← 손님 그림을 작게(약 100px) 나란히
│   팥×2         팥×1 슈×1    슈×3         │  ← 말풍선 대신 작은 주문표 + 인내심 바
│   ▓▓▓▓░        ▓▓▓░░        ▓░░░░        │
│ ════════════ 카운터 ═══════════════════  │
│        ┌────┬────┬────┐                │
│        │ 틀 │ 틀 │ 🔒 │                │  ← 3×3 그대로, 안 산 칸은 잠김 표시
│        ├────┼────┼────┤                │
│        │ 틀 │ 틀 │ 🔒 │                │
│        └────┴────┴────┘                │
│ [팥봉투 3][슈봉투 1] [반죽][팥][슈][꼬챙이] │  ← 봉투 2개 + 도구 4개
└──────────────────────────────────────┘
```

- **손님 그림 크기:** 지금(166px)보다 작은 약 100px로 셋이 나란히 섭니다.
- **대사:** 손님이 처음 들어올 때만 짧은 말풍선(1~2초)으로 보여 주고, 그다음에는 작은 **주문표**로 바뀝니다. 아줌마 대사처럼 개성 있는 대사는 이 들어올 때의 말풍선에서 살립니다.
- **누구에게 건넬지 고르기:** 봉투를 누르면 **그 종류를 주문한 손님 중 가장 오래 기다린 손님**에게 자동으로 갑니다. 원하는 손님을 직접 고르고 싶으면 손님을 먼저 눌러 선택합니다. 선택한 손님에게는 테두리가 생깁니다.
- **잠긴 틀:** 2×2만 쓰는 초반에도 3×3 칸을 다 보여 주고, 안 산 칸에 자물쇠를 표시합니다. 업그레이드하고 싶은 마음이 생기게 하기 위해서입니다.
- **타임어택 모드**는 지금 화면 그대로 둡니다. 두 모드가 같은 화면을 쓰면 타임어택까지 흔들리기 때문입니다.

## 8. 엔딩과 랭킹

### 게임 오버
- 만족도가 0%가 되면 장사가 바로 끝나고 "손님들이 발길을 끊었어요… 가게 문을 닫았습니다" 화면이 나옵니다.
- 버튼: **그날 처음부터 다시** / 처음 화면으로
- **[추가]** "그날 처음부터 다시"는 그날 아침 저장 상태(돈, 업그레이드, 만족도)로 돌아갑니다. 20분짜리 게임을 처음부터 다시 하게 하면 너무 가혹하기 때문입니다. 다만 **다시 하기를 한 번이라도 쓰면 랭킹에 표시**합니다(🔄). 확인이 필요한 부분입니다(10장).

### 엔딩 (Day 15 완주) [추가]
마지막 날 만족도에 따라 엔딩 그림과 문구를 다르게 보여 줍니다.

| 만족도 | 엔딩 |
|---|---|
| 90% 이상 | ⭐ **동네 명물 엔딩**: "줄 서서 먹는 집이 되었어요!" |
| 60~89% | **단골 가게 엔딩**: "내년 겨울에도 꼭 와 달래요" |
| 1~59% | **무사 완주 엔딩**: "힘들었지만 보름을 버텼어요" |

### 랭킹
- 점수는 **엔딩 때 가진 돈**입니다 (사용자 아이디어 그대로).
- 동점이면 만족도가 높은 쪽이 위입니다.
- 1단계: 이 기기 안에서 **상위 10개** 기록(이름 3~8자 입력, 날짜, 엔딩 종류).
- 2단계(나중): **온라인 랭킹** (Supabase 또는 Firebase). 점수를 기기에서 바로 보내면 조작할 수 있으니, 최소한 점수 상한 검사와 플레이 기록 요약을 함께 보냅니다.

## 9. 저장 (중간 저장 기능)

### 무엇을, 언제 저장하나
- **[변경] 저장 시점:** 장사 도중 상태(틀 9칸의 굽기 상태, 손님 인내심 등)까지 저장하면 복잡하고, 저장·불러오기로 실수를 되돌리는 꼼수도 생깁니다. 그래서 **하루가 시작될 때(상점에서 나올 때)** 저장합니다.
  - 장사 도중에 앱을 끄면, 다음에 **그날 아침부터** 이어서 합니다.
  - 상점에서 업그레이드를 살 때마다도 바로 저장합니다.
- 저장 내용:
```js
{
  version: 1,
  day: 7,                 // 다음에 시작할 날
  money: 48200,
  satisfaction: 84,
  upgrades: { molds: 1, fire: 2, plate: 0, bag: 1, sign: 0, price: 0 },  // 단계
  stats: { sold: 312, missed: 4, retries: 0 },  // 엔딩·랭킹용 누적 기록
  settings: { sound: true },
  savedAt: 1730790000000,
}
```

### 보내 주신 저장 코드 검토
보내 주신 코드는 저장 방식이 탄탄해서 **뼈대를 그대로 씁니다.**
- localStorage에 저장하고, IndexedDB에 한 벌 더 저장(미러)
- 저장 내용 검사(`validSave`), 예전 형식 변환 자리(`normalizeSave`)
- 화면을 벗어날 때(`visibilitychange`, `pagehide`) 저장
- 파일로 백업하기(`exportFile`)

다만 이 게임에 맞게 몇 가지를 바꿉니다.

| 보내 주신 코드 | 이 게임에서는 |
|---|---|
| `gold`, `stands` | `money`, `day`, `satisfaction`, `upgrades`(단계 숫자) |
| `grantOffline()` (자리 비운 동안 돈 벌기) | **빼기**: 방치형 게임용 기능이라 스토리 모드와 맞지 않습니다 |
| 8초마다 묶어서 저장 | **빼기**: 하루 시작과 업그레이드 구매 때만 저장하면 충분합니다 |
| 키 이름 `bungeoppang-save-v1` | `cnation-bb-story-v1` (다른 게임과 섞이지 않게) |
| `validSave` 검사 | `day`가 1~15인지, `satisfaction`이 0~100인지, 업그레이드 단계가 최대값 안인지까지 검사 |
| `restoreNewer()` | 보내 주신 코드가 중간에서 잘려 있어서, "IndexedDB 쪽이 더 최근이면 그쪽으로 복구"하는 뜻대로 새로 씁니다 |
| 저장 실패 시 `alert` | 게임 화면 안의 안내창으로 바꿉니다 |

- 타이틀 화면의 스토리 모드 버튼은 저장이 있으면 **"이어하기 (Day 7)"**와 **"새로 시작"** 두 개를 보여 줍니다. 새로 시작하면 "저장된 기록이 지워져요"라고 확인합니다.
- 타임어택 최고 기록은 지금처럼 따로 저장합니다.

## 10. 사용자 확인이 필요한 결정

1. **게임 오버 뒤 "그날 다시 하기"**를 허용할까요? (추천: 허용하고 랭킹에 🔄 표시)
2. **타임어택 모드 이름**: 3분 챌린지 / 번개 장사 / 붕어빵 러시 / 기타
3. **덜 익은 붕어빵을 꺼낼 수 있게** 하는 것(4장 [추가])이 괜찮을까요? 빼면 "덜 익은 붕어빵" 벌점은 없어집니다.
4. **타임어택 모드에도 슈크림**을 넣을까요? (추천: 넣지 않고 지금 그대로 두기)
5. **이야기**: 하루 시작 때 한두 줄짜리 이야기(예: "Day 4. 손님이 슈크림 붕어빵은 없냐고 물어봤다.")를 넣을까요? 스토리 모드라는 이름에 맞게 넣는 것을 추천합니다.

## 11. 만드는 순서 (단계별 버전)

한 번에 다 만들면 확인하기 어렵습니다. 단계마다 직접 플레이해 보고 다음 단계로 넘어갑니다.

| 단계 | 버전 | 내용 | 화면 개편 |
|---|---|---|---|
| **1단계** | v1.1.0 | 모드 선택, Day 1~15 흐름, 2×2 → 3×3 틀, 상점 6종, 만족도, 저장·이어하기, 게임 오버·엔딩, 기기 안 랭킹 (**팥만, 손님 1명**) | 작게 (HUD 만족도, 잠긴 틀, 상점·엔딩 화면) |
| **2단계** | v1.2.0 | 손님 여러 명, 슈크림, 봉투 2개, 종류별 터치, 섞은 주문, 덜 익은 붕어빵 | **크게** (6장 배치) |
| **3단계** | v1.3.0 | 특별 손님 (배달 기사, 흥정왕 아줌마, 단체 주문, 부자 손님 …) | 손님 규칙만 추가 |
| **4단계** | v1.4.0 | 온라인 랭킹 (Supabase/Firebase) | 랭킹 화면 |

- 1단계는 지금 화면을 거의 그대로 쓰면서 **스토리의 뼈대와 돈 밸런스**를 먼저 확인합니다.
- 2단계에서 화면을 한 번에 개편합니다. 손님 여러 명과 봉투 두 개는 둘 다 화면 배치를 바꾸기 때문에, 따로 하면 두 번 고치게 됩니다.
